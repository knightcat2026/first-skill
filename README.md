# Phone Clean Guard · 手机防误装净化

给长辈机和备用机用的 AI Skill：**保留用户资料，减少广告、智能推荐、跳转和误装入口。**

功能边界：**只关闭功能和入口，不删除任何用户资料，不卸载任何已安装应用，不删除手机中保存的 APK 安装包，不关闭手机更新功能。** 系统更新、安全补丁、应用更新及其原有自动更新偏好均保留。

它来自一次真实手机维护的经验，但不是把那台手机的删包记录照搬给所有人。默认通过系统设置关闭入口，必要时可恢复地停用少量已核实的推荐组件，保留正常安装和系统安全功能。

这是可交给 Codex 等支持 `SKILL.md` 的 AI 工具使用的工作流，附带 Python 辅助工具；不是手机 App，也不是无需判断的一键“净化 ROM”。使用者需要拥有手机或获得机主授权。

## 能做什么

- 识别主系统，区分 Android／旧版鸿蒙与原生 HarmonyOS，避免误用命令。
- 分层检查桌面、负一屏、锁屏、云文件夹、浏览器、应用市场、快应用、通知、输入法和主题的推荐入口。
- 记录原状态、功能影响与恢复方法，逐项核验；不清空应用资料、不卸载用户软件、不刷机。
- Android 辅助工具提供只读审计、明确选项的计划、停用日志、回读核验和原状态恢复。
- 默认保留主动安装软件的能力。全局禁装、家长控制等额外限制需要单独选择，本版不自动设置。
- 保留应用市场、浏览器、快应用引擎及更新组件；分别处理其推荐和误装入口，不为净化冻结整套应用或更新渠道。

**不能保证任何系统上的所有广告和误装都永久消失。** 关闭个性化仍可能看到普通广告；网页内容、应用更新、系统升级可能带来新入口。报告会区分“已关闭 / 仍有入口 / 此版本无此功能 / 未验证”。

## 兼容范围与验证程度

| 环境 | 当前能力 | 验证情况 |
| --- | --- | --- |
| Android API 26+，包括 Android 主系统的各品牌定制系统 | ADB 只读检查 + 按实际界面关闭入口 | 辅助工具使用合成设备测试；并非所有机型均经真机测试 |
| HarmonyOS 4.x 及以下 | 确认 Android 能力后使用上述路线 | 历史手工维护经验来自 HONOR 9X / HLK-AL00 / HarmonyOS 3.0.0.170 |
| 原生 HarmonyOS 5+ / NEXT | 官方 HDC 识别指导 + 按实际界面审查 | 本版没有原生鸿蒙包操作脚本，没有原生鸿蒙真机测试 |
| 自动停用 | 仅档案列出的型号、系统版本、构建号等条件全部匹配，人工选择候选组件 | 初始档案仅一个、未记录历史完整固件指纹；字段匹配不是此停用脚本的真机验证 |
| 老旧版本、未知系统、容器、工作资料或受管理设备 | 只读确认与界面指导 | 不跨空间、不绕过管理员限制 |

没有匹配档案也可以按界面完成处理。**跨系统工作流支持不等于跨机型自动删包。** 详细分流和官方依据见 [系统兼容](skills/phone-clean-guard/references/platforms.md) 与 [来源](skills/phone-clean-guard/references/sources.md)。

## 在 AI 工具中使用

1. 下载项目，把 `skills/phone-clean-guard` 这个完整文件夹放到你的 AI 工具支持的技能目录。Codex 项目级使用可放在项目的 `.agents/skills/phone-clean-guard` 下；目录中应能直接看到 `SKILL.md`。重新打开项目，确认技能已被识别。
2. 让 AI 使用这个 Skill，例如：

   > 使用 $phone-clean-guard。把这台手机整理成长辈备用机，保留照片、聊天和所有用户资料。关闭广告推荐与误装入口，保留正常安装能力。先检查实际系统并列出具体计划，再按我的授权执行，给我恢复方法。

3. 如使用 ADB 辅助工具，准备 Python 3.10+ 和 [官方 Android Platform Tools](https://developer.android.com/tools/releases/platform-tools)。通过能传数据的 USB 线连接、解锁手机，在开发者选项中开启 USB 调试，并在手机上确认这台电脑的调试授权。只开启开发者选项还不够。原生鸿蒙按自己的工具路线处理。

AI 工具需要具备可用的设备连接或界面操作能力；本项目不附带远程控制 App、绕过授权工具或驱动包。没有界面工具时，Skill 会指导机主在手机上操作，未验证的项目会保留为未验证。

下载 Skill 后，需要让 AI 工具加载并调用它；Skill 不会自行运行或常驻手机。

## 系统更新以后

正常更新手机即可，不为保留净化效果阻止更新。更新可能保留设置，也可能重新开启部分入口；有需要时再次运行本 Skill。

再次运行会重新识别系统和版本、新建维护记录，检查哪些入口重新出现，仅处理需要关闭的项。不会重放旧命令或把旧固件档案套在新系统上；遇到新版本缺少自动档案时按实际界面处理。

## 辅助工具的执行方式

在项目根目录，用 `python skills/phone-clean-guard/scripts/phone_guard.py --help` 查看入口。Windows 没有 `python` 命令时，可改用已安装 Python 的完整路径或 `py -3`。

```text
audit → plan → 人工检查计划及影响 → apply → verify → 界面与功能验收
                                         ↘ restore（需要恢复时）
```

`audit` 和 `plan` 不修改手机；`apply` 只执行已审查的独立推荐组件停用操作，保留安装包与数据。`verify` 同时核对基线已安装应用仍存在，更新设置与实际入口另行界面验收。此工具不自动操作各应用的界面开关。具体命令、日志和故障恢复见 [辅助工具说明](skills/phone-clean-guard/references/adb-helper.md)，界面处理见 [界面操作指南](skills/phone-clean-guard/references/ui-playbook.md)。

## 隐私与数据

维护报告、应用清单、UI 截图和界面 XML 可能透露个人信息。把会话目录放在仓库外的私密位置，**不要上传实际手机报告**。工具不会读取照片、联系人或聊天内容，不连接云服务；本地状态记录并不等于完整数据备份，也不加密会话目录。

公开项目只包含通用规则、厂商公开固件信息和合成测试。不要提交序列号、账号、Wi-Fi 信息、真实设备清单、安装包、调试日志或备份。发布用清单由 `tools/package_release.py` 明确限定，不会把整个工作目录打包。

## 开发与分享

```bash
python -m unittest discover -s tests -v
python tools/package_release.py --out ../phone-clean-guard-v0.1.1.zip
```

打包器仅收录本项目的明确发布文件，并拒绝覆盖已有压缩包。测试使用模拟设备，不会连接真实手机。新机型档案的证据与测试要求见 [贡献指南](CONTRIBUTING.md)。

发布到 GitHub：新建仓库 `phone-clean-guard`，解压发布包后上传其中的项目文件。`README.md`、`LICENSE`、`skills`、`tests` 和 `tools` 应在仓库根目录；不要上传自己维护手机时生成的会话目录。此项目没有自动发布、遥测或后台常驻任务。
