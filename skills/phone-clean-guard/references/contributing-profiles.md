# 新机型档案要求

未匹配设备优先走设置界面，不临时扩大现有档案。新档案是可审查的贡献，不能在同一维护会话里仅为绕过拒绝而创建。

1. 在机主授权的测试设备上确认主系统、品牌/厂商、型号、设备代号、Android release/API、完整构建号与 fingerprint；原生鸿蒙不进入 Android 档案。新增档案应包含经核对的完整 fingerprint，不继承历史档案缺失该证据的限制。每个适用条件都必须有设备或官方资料依据。
2. 对每个候选包确认实际标签、作用、依赖、默认角色、停用后损失和恢复方法。包名含有 ads、recommend、smart 不能独立证明安全。只收录独立推荐组件；禁止添加用户应用、浏览器、应用市场、整套快应用引擎、桌面、输入法、账号、安装器、主题框架、系统/安全补丁/应用更新、支付、无障碍或共享核心服务。不删任何已安装应用、用户资料或已保存 APK，不改变更新偏好。
3. 附上不含个人信息的最小证据摘要。不能复制真实整机应用列表、序列号、截图、用户资料、完整 dumpsys/settings 或厂商 APK；也不能未经许可搬运第三方数据库。
4. 只添加可恢复的 `disable-user` 候选。匹配字段至少保持当前档案的精度，不使用通配型号或“所有同品牌”。记录未进行的测试，不能把模拟结果说成真机成功。
5. 用独立测试验证不匹配固件拒绝、保护对象拒绝、原状态准确恢复、中断恢复及核心功能。真机测试另行获得授权，不在普通单元测试或 CI 连接设备。
6. 经独立审查再合入、版本化发布。若系统或应用更新改变依赖，先缩小/移除适用范围，不猜测继续支持。

`profiles.json` 中最初的 HONOR 9X 档案来自一次历史手工维护经验；它提供有限候选依据，不代表本 Python 停用工具已有真机验证。后续贡献应逐步补足验证覆盖，而不是只增加包数量。
